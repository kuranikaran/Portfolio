# Proposed CNA Scope and Operating Procedure

**Karan Kurani | Independent Security Research**  
**Date:** 11 October 2026  
**Status:** Proposed for CVE Program review. Not an approved CNA scope or current delegation of CVE assignment authority.

## Proposed scope definition

Vulnerabilities discovered or coordinated through Karan Kurani's independent security research activity in publicly available third-party software, where this scope is approved by the applicable CVE Root and a more specifically scoped CNA does not take responsibility for the assignment, following the current CVE Program rules and Root guidance.

**Boundaries:** No assumption of authority over products maintained by an existing supplier CNA; no blanket authority to assign for vulnerabilities merely because I reported them. Confidential employer or client findings are excluded unless the owning supplier explicitly authorizes disclosure and assignment coordination.

## Intended operating process after approval

1. Receive a private report through the published reporting channel; preserve an intake reference and report date.
2. Assess vulnerability evidence, root cause, affected products, affected and fixed versions, uniqueness and duplicate status.
3. Determine the currently applicable CNA scope. Contact the most appropriately scoped CNA and follow the right-of-first-refusal and Root referral rules.
4. Coordinate notification, embargo and the fix or mitigation with the supplier as appropriate; avoid disclosure of sensitive exploitation material during remediation.
5. Only when formally authorized and in scope, assign or reserve a CVE ID using the approved CNA service, confirm vulnerability abstraction, and document an audit trail.
6. Publish a sufficiently detailed, freely accessible vulnerability reference no later than the CVE Record publication, meeting the CVE Program public-reference requirements.
7. Publish the CVE Record in compliance with required content, timelines and release coordination. Under CVE Rules v4.2.0, a CNA must publish a record within 72 hours after publicly disclosing a CVE ID that it assigned.
8. Maintain published advisory and CVE Record corrections, handle disputes and escalate to the Root or CNA of Last Resort where appropriate.

## Intended evidence, service and quality controls

- Traceable reproductions using authorized testing environments, call-path evidence and conservative impact analysis.
- No CVE assignment solely because a scan produced a warning, and no knowingly duplicate CVE assignment.
- Track supplier outreach, published references and requested researcher recognition.
- Contact email monitored for reporter/vendor questions, correction requests and Root communications.
- Separate public advisories from private evidence and non-public customer materials.
